二阶段：搭建 LLM 全局调用 + 会话记忆模块
底层大模型调用层和记忆管理层已完成开发。

## 新增功能
### 1. 统一LLM调用层 (core/llm.py)
功能 说明 LLMMonitor监控器 记录每次模型调用的耗时、入参、出参等信息 参数验证 自动验证消息格式，防止非法输入 统一异常捕获 网络超时、连接错误、认证失败、API错误等 OpenAI兼容接口 chat_completion() 方法支持标准OpenAI格式 流式输出支持 完整的流式生成功能，带日志记录

### 2. 会话记忆管理层 (core/memory.py)
功能 说明 ConversationMemory 会话记忆管理器，支持自动压缩对话历史 对话摘要 基于ConversationSummaryMemory自动生成摘要 分层记忆 短期详细记忆 + 长期摘要记忆 溢出保护 超过阈值自动压缩，防止上下文溢出 序列化支持 to_dict() / from_dict() 支持状态持久化

### 3. 异常体系 (utils/exception.py)
异常类型 触发场景 LLMError 模型调用失败 NetworkError 网络超时或连接错误 ValidationError 参数验证失败 ConfigurationError 配置错误

## 核心模块结构
```
core/
├── __init__.py
├── llm.py           # 企业级LLM封装（含监控和异常处理）
└── memory.py        # 会话记忆管理（自动摘要压缩）
```
## 使用示例
```
# 创建LLM实例
from core import LLMFactory, MemoryFactory

llm = LLMFactory.create_llm(
    api_key="your-api-key",
    base_url="https://your-private-model/v1",
    model_name="gpt-4"
)

# 创建记忆实例
memory = MemoryFactory.create_summary_memory(llm=llm)

# 添加消息
memory.add_user_message("你好")
memory.add_ai_message("你好！我是企业AI助手。")

# 获取历史
history = memory.get_history()
summary = memory.get_summary()
```

## 新增功能
### 1. RAG检索器 (RAGRetriever)
方法 功能 retrieve() 相似度检索，返回top3相关文档 retrieve_and_format() 检索并格式化为prompt可用格式 generate_with_knowledge() 基于知识库生成回答（知识增强） qa() 问答接口，返回答案和参考资料

### 2. 模拟内部文档
文档 内容 coding_standards.md Python编码规范、错误处理、数据库规范 cmake_standards.md CMake配置规范、编译流程、交叉编译 compile_errors.md 链接错误、编译错误、CMake错误解决方案 development_workflow.md Git工作流、代码审查、发布流程

### 3. 核心功能流程
```
文档加载 → 文本切分 → 向量化 → 入库(Chroma) → 检索 → 知识增强 → 回答
```
## 使用示例
```
from knowledge import KnowledgeIngestor, RAGRetriever

# 1. 构建知识库
ingestor = KnowledgeIngestor()
ingestor.ingest_directory("/path/to/docs", file_types=[".txt", ".md"])
ingestor.persist()

# 2. 创建检索器
retriever = RAGRetriever(top_k=3)

# 3. 检索相关文档
results = retriever.retrieve("链接错误 undefined reference")

# 4. 基于知识库回答
answer = retriever.generate_with_knowledge("cmake编译时报错undefined 
reference怎么办？")

# 5. 问答接口（带参考资料）
result = retriever.qa("如何进行代码审查？")
print(result["answer"])
print(result["references"])
```

企业开发专用工具层已完成开发。

## 新增的5个企业开发工具
### 1. 代码生成工具 (CodeGeneratorTool)
- 工具名 : code_generator
- 功能 : 根据结构化参数（编程语言、框架、功能描述）生成符合公司编码规范的代码
- 输入 : language , framework , functionality , requirements
- 输出 : 生成的代码 + 代码说明
### 2. 代码重构工具 (CodeRefactorTool)
- 工具名 : code_refactor
- 功能 : 优化代码结构、降低耦合、保持功能不变
- 支持重构类型 : 性能优化、可读性提升、可维护性改进、安全性增强
- 输入 : code , language , refactor_type , requirements
- 输出 : 重构后的代码 + 修改点列表
### 3. 编译错误分析工具 (CompileErrorAnalyzerTool)
- 工具名 : compile_error_analyzer
- 功能 : 解析编译日志，结合内部知识库返回企业修复方案
- 支持错误类型 : 链接错误、编译错误、CMake错误、运行时错误
- 输入 : error_log , language , build_system
- 输出 : 错误类型 + 错误位置 + 修复方案 + 建议
### 4. 开发文档生成工具 (DocGeneratorTool)
- 工具名 : doc_generator
- 功能 : 根据代码生成公司格式注释、接口文档
- 支持文档类型 : API接口文档、类文档、函数文档、README文档
- 输入 : code , language , doc_type , format
- 输出 : 生成的文档内容
### 5. 自动化脚本工具 (ScriptGeneratorTool)
- 工具名 : script_generator
- 功能 : 生成内部编译、打包、CI简易脚本
- 支持脚本类型 : 编译构建脚本、部署脚本、测试脚本、CI配置
- 输入 : script_type , language , requirements
- 输出 : 生成的脚本内容




阶段五：开发 Agent 核心调度 + 工具路由
Agent核心调度层已完成开发。

## 核心功能实现
### 1. DevEnterpriseAgent 类核心机制
功能 实现方式 工具路由映射 手动维护 _tool_registry 字典： {工具名字符串: 工具实例} LLM自主决策 系统提示词引导LLM分析意图、选择工具、抽取参数 路由解析 自研 _parse_tool_calls() 解析 <function_calls> 标签 反射调用 _execute_tool() 根据工具名动态调用对应工具 多轮循环 run() 方法支持最多5轮迭代，任务不完成不终止 知识增强 自动调用知识库检索，结果注入prompt上下文

### 2. 工具调用格式
LLM输出格式：

```
<function_calls>
[
  {
    "tool_name": "code_generator",
    "params": {
      "language": "python",
      "functionality": "创建用户登录API"
    }
  }
]
</function_calls>
```
### 3. 执行流程
```
用户输入 → 知识库检索 → 构建prompt → LLM思考 → 解析工具调用 → 执行工具 → 循环/结束
```
